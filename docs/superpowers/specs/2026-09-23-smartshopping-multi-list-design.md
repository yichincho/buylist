# SmartShopping v0.2.2：多清單與多人需求合併設計

日期：2026-09-23  
狀態：使用者已確認設計方向；待規格審閱

## 1. 目標

在現有 SmartShopping Android v0.2.1 專案上新增本機多清單管理，讓多人可依序提供文字或圖片，內容都加入目前清單。加入文字、AI 整理與截圖辨識都不得清除先前已加入的品項。

使用者可清除輸入框文字、清空目前清單，或一鍵保存目前清單並開啟空白新清單。歷史清單和圖片可在 App 內找回。Gemini 作為預設 AI 服務，使用者自行提供 API Key；保留 DeepSeek 選項與本機離線解析。

## 2. 已確認的需求與限制

- 不記錄需求提出者；多人需求直接合併。
- 一台手機本機使用，不加入帳號或雲端同步。
- 文字、AI 整理結果及截圖辨識結果以追加方式寫入目前清單。
- 相同或相似品項不自動刪除，避免誤合併不同數量或不同用途的需求。
- 清除文字只清空輸入框草稿，不刪除已加入的品項或圖片。
- 清空目前清單會清除該清單的全部品項及圖片；執行前顯示確認。
- 「儲存並開新清單」保留目前清單供日後切換，建立空白清單並切換至新清單。
- 新清單以日期時間自動命名，不增加必填步驟。
- 既有 v0.2.1 資料必須遷移並保留。
- Gemini 與 DeepSeek 的 Key 由使用者自行輸入，使用 Android Keystore 加密保存，不寫入原始碼、APK、日誌或備份。
- AI 或網路失敗時，保留草稿並以 LocalParser 離線拆分；已保存內容仍可正常編輯與勾選。

## 3. 選定方案

採用 SQLite 多清單資料模型。新增 shopping_lists 表，items 和 images 增加 list_id 欄位；目前清單 ID 保存在本機偏好設定。切換清單時，畫面從所選清單讀取品項與圖片。圖片仍保存在 App 私有檔案目錄，資料列歸屬到同一清單。

不採用匯出 JSON 後清空單張工作清單的方式，因為這會使歷史清單和圖片不容易在 App 內找回。

## 4. 操作與資料流程

### 4.1 文字輸入

- 保留原有多行輸入、貼上及繁體中文語音輸入。
- 在文字框旁新增「清除文字」，只清除目前清單草稿。
- 新增「加入清單」按鈕，使用 LocalParser 拆分文字並追加至目前清單，不需要 API Key。
- 加入成功後清空輸入框，讓下一位使用者可以直接輸入。
- 新增「AI 整理並加入」；成功或離線備援解析後追加品項。成功追加後清空輸入框；請求失敗且沒有產生備援項目時保留草稿。
- 切換清單時保存並載入各清單自己的草稿，避免把上一張清單的草稿誤加到另一張清單。

### 4.2 圖片與截圖辨識

- LINE 分享、相簿及剪貼簿匯入的商品圖片歸屬目前清單。
- 新清單起始時不顯示其他清單的圖片。
- 原有截圖辨識結果追加至目前清單，不再取代品項。
- 參考圖片仍留在裝置內；只有使用者透過截圖辨識功能提交的圖片會傳給當前選取的 AI 服務。

### 4.3 多清單

- 頂部顯示目前清單名稱，並提供清單紀錄切換入口。
- 清單紀錄列出名稱、建立時間和內容數量；使用者可開啟舊清單。
- 「儲存並開新清單」保留目前內容，建立名稱含日期時間的空白清單，切換至該清單，並清空輸入框。
- 清除整張清單只清除目前清單的品項及圖片，不刪除清單紀錄。
- 刪除歷史清單需另行確認；刪除後才清除其圖片檔案。若刪除的是目前清單，建立一張新的空白清單並保持 App 可用。

### 4.4 AI 提供者

- 新安裝及升級後的預設提供者為 Gemini。
- 預設 Gemini 模型為 gemini-3.1-flash-lite；設定頁顯示 Gemini / DeepSeek 提供者選擇、對應 Key 輸入、儲存、清除及測試連線。
- Gemini Key 和既有 DeepSeek Key 分別加密保存；升級時保留 v0.2.1 的 DeepSeek Key。
- API Key 不得放在 URL、日誌、APK 或未加密的偏好設定。
- Gemini API 直接呼叫 Google REST API；使用 JSON 結構化輸出，截圖辨識採 inline image data。
- 無 Key、配額限制、無網路、HTTP 錯誤、逾時或無效 JSON 時，回報可理解的訊息，文字功能改用本機解析。
- Key 由每位使用者自行設定；不提供共用 Key、不在 APK 內附 Key。Google 的免費方案和配額依所選模型、專案及當前政策而異。

## 5. 資料模型與遷移

### shopping_lists

- id：主鍵
- name：清單名稱
- created_at：建立時間
- updated_at：最近更新時間

### items

保留既有欄位並新增 list_id。每次新增都使用目前清單 ID，sort_order 在同一清單內遞增。

### images

保留既有欄位並新增 list_id。每張圖片資料列只屬於一張清單。

### 草稿及設定

- 草稿以清單 ID 為索引存於本機偏好設定；v0.2.1 全域草稿遷移至舊版清單。
- active_list_id 持久化；App 重啟後回到上次使用的清單。
- AI 提供者保存為 Gemini 或 DeepSeek，預設 Gemini。
- 既有 DeepSeek IV/ciphertext 在升級時可繼續讀取；新增 Gemini Key 以不同偏好設定鍵加密保存。

### v0.2.1 → v0.2.2 遷移

- 資料庫版本由 1 升至 2。
- 建立 shopping_lists，新增一筆「v0.2.1 匯入清單」。
- 將舊 items 和 images 的 list_id 設為該筆匯入清單 ID。
- 遷移既有草稿及 DeepSeek Key，不刪除圖片檔案。
- 新安裝時建立「採買清單」作為第一張清單。
- 所有遷移步驟在 SQLite transaction 中完成；失敗時不得留下半套資料。

## 6. 主要元件

- ShoppingDb：清單 CRUD、依 list_id 查詢/寫入品項及圖片、清除目前清單和資料庫遷移。
- MainActivity：清單切換、新增文字、清除文字、清除清單及儲存開新清單的操作。
- LocalParser：純本機文字拆分；追加操作不依賴網路。
- GeminiClient：Gemini REST、JSON 結構化輸出、文字整理及截圖辨識。
- DeepSeekClient：保留現有文字整理及截圖辨識能力。
- SecureKeyStore：每個提供者獨立加密保存 Key，並相容現有 DeepSeek Key 格式。

目前 ZIP 為精簡 Java/SQLite 專案，不含 Gradle wrapper 或既有 Git 歷史；實作沿用此專案結構，不進行 Kotlin/Room 全面重寫。

## 7. 錯誤與資料安全

- 一次清除目前清單前顯示確認，提示會移除目前清單中的全部品項與圖片。
- 刪除清單時先從資料庫移除關聯資料，再刪除私有圖片檔；若 DB 操作失敗，不先刪除檔案。
- AI 回應解析完成前不修改任何既有品項。
- API Key 儲存錯誤、AI 失敗及圖片單筆匯入失敗都不應讓 App 閃退。
- 不在終端輸出、錯誤訊息或測試 log 中輸出 API Key。
- 一般商品圖片不送至 AI；只有使用者明確啟動截圖辨識時才上傳該張圖片。

## 8. 驗收標準

1. 從 v0.2.1 升級後，原有品項、完成狀態、圖片與草稿仍可讀取。
2. 將文字貼入並按「加入清單」，新增品項出現在原清單末端；先前品項不消失。
3. 加入後輸入框變空；「清除文字」不刪除清單內品項或圖片。
4. AI 整理文字與截圖辨識的結果追加，不覆蓋已加入的品項。
5. 圖片與品項依目前清單隔離；切換至另一張清單時不混入。
6. 按「儲存並開新清單」後，舊清單仍可開啟，新清單沒有舊品項、圖片或草稿。
7. 清除整張清單只清除當前清單，歷史其他清單保持不變。
8. 刪除歷史清單需確認，並刪除該清單私有圖片檔案。
9. Gemini 為預設 AI；使用者自行輸入 Key 後可測試文字與圖片請求；DeepSeek 既有 Key/功能仍可選用。
10. 沒有 Key 或網路時，文字仍可本機拆分加入清單。
11. SQLite 遷移與純邏輯測試通過；APK 建置及簽署驗證通過；APK 和原始碼掃描均未發現內嵌 API Key。

## 9. 不包含

- 多裝置雲端同步或多人即時共同編輯。
- 輸入者姓名、帳號登入或需求者標籤。
- 條碼、價格、預算或賣場走道排序功能。
- 自動合併同名文字列。
- 將一般商品參考圖片自動 OCR。
